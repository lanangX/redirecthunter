# Example --accounts-file for `redirecthunter bl-check --accounts-file` /
# `redirecthunter bl-chain --accounts-file`.
#
# Usage:
#   redirecthunter bl-check backlinks.txt -d medilana.id --accounts-file this-file.txt
#
# Use this when ONE domain needs MANY different sessions -- e.g. checking
# placements posted from 30 different social-media accounts on the same
# platform, where each placement needs its own Cookie. See
# docs/BACKLINK_GUIDE.md#account-scoped-sessions-accounts-file.
#
# Format: one header per line, "account_id|Name: Value". Repeat the same
# account_id on further lines to register more than one header for it:
#
#   account_001|Cookie: session=xxxxx
#   account_001|User-Agent: Mozilla/5.0
#   account_057|Cookie: session=yyyyy
#
# A bare "account_id|" line (nothing after the |) explicitly registers
# that account with zero headers -- valid and intentional, distinct from
# the account_id never appearing in this file at all. Use it to document
# "this account is deliberately checked with no special headers."
#
# Pair this registry with input rows prefixed "account_id|URL" (TXT), an
# "account_id" column (CSV), or a "account_id" key (JSON) -- see
# examples/tier1.txt for a matching input file that references
# account_001 and account_002 below.
#
# Any account_id referenced by an input row but missing from this file
# is a hard error: bl-check/bl-chain refuse to start and list every
# missing account_id, before any request is sent. There is no silent
# fallback to an anonymous request.
#
# --------------------------------------------------------------------------
# HOW TO GET THE RIGHT COOKIE VALUE for each account:
#
# Recommended: use the bundled rh-cookie-copier browser extension
# (../rh-cookie-copier) -- log in as that account, click the extension
# icon, pick "Account line", type a username/label, and it copies a
# ready-to-paste "account_id|Cookie: ..." line straight to your
# clipboard. See rh-cookie-copier/README.md for the (under-a-minute)
# local install steps. Repeat once per account.
#
# Fallback (no extension): open DevTools' *Network* tab (not
# Application/Storage/Cookies), reload the page, click the top document
# request, and copy everything after "Cookie:" in its Request Headers --
# that's exactly what the browser sends, so you don't need to guess
# which individual cookie name is "the" session cookie.
#
# Keep this file OUT of version control once you fill in real values --
# these are live session credentials, one set per account. Treat it like
# a password file. (Add its real filename to .gitignore; this example
# file is safe to commit since it has no real values.)
# --------------------------------------------------------------------------
