Perbaikan Body Link

Daftar pola body_link unik yang tidak persis sama dengan target scan (—) setelah dinormalisasi (skema/www./port/trailing slash diabaikan). Sebagian memang tidak bisa diperbaiki — placement yang gagal biasanya mendarat di halaman generik milik layanan itu sendiri (error Cloudflare, halaman dukungan, dst), bukan target yang terpotong. Yang paling sering layak diperbaiki: protokol dobel (http://https://…) atau slug tambahan yang menempel setelah target (mis. /management.html). Cara paling gampang: buka baris hasilnya di tabel Results, klik untuk buka drawer, dan perbaiki langsung dari sana — tabel di bawah ini cuma untuk meninjau/mencari pola mana saja yang masih perlu ditangani. Satu perbaikan berlaku untuk SEMUA source URL yang menghasilkan body_link yang sama persis (lihat kolom "Baris" — banyak redirector berbeda sering menghasilkan mangling yang identik), dan tersimpan di browser ini walau file dibuka lagi nanti (lihat docs/MEMORY.md v1.9).

Perbaikan Source URL

Ini untuk kesalahan pada baris source URL itu sendiri (template mentah dari examples/urls.txt, dengan {TARGET} masih utuh) — bukan mismatch body_link seperti tab sebelah. Contoh khasnya: typo di dalam salah satu baris urls.txt yang membuat hasil ekspansi jadi rusak, misalnya karakter nyasar sebelum {TARGET} yang membuat skema URL dobel/rusak seperti http://t{TARGET} → http://thttps://…. Baris yang ditandai ⚠ kemungkinan salah terdeteksi otomatis dari pola skema ganda pada hasil ekspansinya — ini cuma bantuan urutan/sorot, bukan syarat: Anda bisa mengedit source URL mana pun di bawah ini, termasuk yang tidak ditandai, dan kotak edit yang sama juga selalu muncul di drawer detail tabel Results (bukan cuma saat ditandai ⚠) — jadi kalau menemukan source URL aneh dalam bentuk apa pun, tidak harus berupa skema ganda, tetap bisa langsung diperbaiki dari sana. Perbaikan tersimpan di browser ini dan otomatis diterapkan ke tampilan/expor, dan — kalau folder proyek sudah disambungkan (lihat layar muat file) — bisa langsung disinkronkan ke file examples/urls.txt yang asli, termasuk membersihkan baris duplikat.

Spam Blacklist

Satu pola (regex) per baris — format sama seperti Wikimedia spam blacklist. Baris kosong dan baris berawalan # diabaikan; komentar setelah # di akhir baris juga diabaikan. Dicocokkan (case-insensitive) ke final_url dan body_link setiap hasil (bukan ke source_url, karena source URL dibuat oleh RedirectHunter sendiri sebagai probe — lihat docs/MEMORY.md). Daftar ini bisa Anda edit langsung, muat dari file .txt lain, atau unduh kembali — semuanya tersimpan hanya di sesi browser ini, tidak otomatis ikut ke file .db.

Dokumentasi

Dibaca langsung dari docs/CLI_REFERENCE.md di folder proyek yang tersambung (tombol "Buka folder proyek" di layar muat file) — bukan salinan yang di-hardcode di sini, supaya tidak pernah basi dibanding CLI-nya sendiri. Setiap command punya tombol salin sendiri.

Folder file backlink lokal Anda (untuk bl-check/bl-chain, mis. tier1.txt, tier2.txt, bl-check-accounts.txt — file yang biasanya tidak di-commit ke git karena berisi data nyata): isi nama foldernya di bawah, dan setiap command yang menyebut file-file itu di bawah examples/ akan otomatis ikut memakai folder ini saat disalin. Tersimpan di browser ini (tidak hilang saat dibuka lagi). Tidak memengaruhi examples/urls.txt — itu tetap untuk scan dan sengaja tidak ikut berubah.
